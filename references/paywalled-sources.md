# 流程卡：付费墙信源取证

适用场景：核查的关键信源位于付费墙后（《南华早报》《华尔街日报》《金融时报》《经济学人》《日经》、彭博、《明镜》等），而该报道是某个子命题的唯一直接依据。

目标：在**不绕过付费墙**的前提下，榨取尽可能多可举证的公开信息，并把「哪些内容我直接看到了、哪些只是从转述得知」写清楚。

## 先立三条纪律

1. **不绕墙**。不使用付费墙绕过服务、第三方全文镜像、非授权 PDF 转存。默认只采公开下发的内容。
2. **墙后的细节不等于已知为真**。看不到原文时，转载摘要只是「据说原文如此」，必须另有独立信源佐证才能写进结论。
3. **必须披露取证层级**。报告里要能看出每条细节来自 L1/L2/L3/L4 哪一级，否则读者会默认作者读完了全文。

## 取证五级阶梯

| 级别 | 内容 | 是否可直接引用 | 说明 |
|---|---|---|---|
| **L0** | 墙内全文 | ❌ | 未订阅即未获得。不得声称读过 |
| **L1** | 公开元数据 | ✅ | 标题、副题、作者、发布时间戳、URL slug、导语 |
| **L2** | 公开可见正文段落 | ✅ | 多数付费墙前 2–4 段在墙外；导语段常已含核心数字 |
| **L3** | 独立转载摘要 | ⚠️ 需溯源 | 只能作线索，须判定独立性并交叉验证 |
| **L4** | 其他信源（一手/通讯社） | ✅ | 政府通稿、通讯社独立采访、官方数据库 |

## 第一步：判定墙的类型

不同类型的可采范围差别很大，先看一眼。

| 类型 | 特征 | 可采 |
|---|---|---|
| 计量墙（metered） | 每月 N 篇免费 | L2 通常完整可读 |
| 硬墙（hard paywall） | 全文遮挡，正文不下发 | 只能到 L1/L2 |
| 注册墙 | 免费注册即读 | 若不便注册则按硬墙处理 |
| 软墙 / JS 遮挡 | 正文在 HTML 中存在，仅被 CSS/JS 折叠 | **灰色地带**。默认不用；确需使用时须经编辑确认并在报告中披露 |
| 反爬墙 | 返回 403 / 验证码 | 用存档快照（archive.today 常留全文）替代 |

## 第二步：L1 元数据榨取（成本最低、价值最高）

按顺序做：

1. 直接抓 URL，看 HTTP 状态与首屏。
2. 读 **JSON-LD 结构化数据**（`<script type="application/ld+json">`，`@type: NewsArticle`），字段常含 `headline`、`datePublished`、`dateModified`、`author.name`、`description`。这是**最可靠的日期与作者来源**，比页面显示更准。
3. 读 **og:/twitter: meta 标签**（`og:title`、`og:description`、`article:published_time`）。
4. 记录 **URL slug**——slug 里的词组往往就是原标题的压缩版，可用于反证标题是否被二次加工过。
5. **精确标题串全网搜**（加引号），观察有哪些站点转载、日期是否漂移。

> 时间戳时区要写清。SCMP 显示的是香港时间（HKT），转载站常直接照搬成 UTC 或当地时间，能差一天。

## 第三步：L2 公开页面段落

- 墙前导语段经常已经把**最核心的数**写进去了（本案：中方约 50 美元 / 至少 120–130 美元、俄方 250–260 美元全在公开段）。
- 用 `references/tools.md` 里的运算符配合 `site:` 把公开段与站内其他报道串起来读，同一记者/同一选题常互文。
- 存档优先：`web.archive.org/save`、`archive.today`。**存档快照往往比现页可见内容更多，且冻结了时间戳**，是付费墙信源最实用的替代取证入口。

## 第四步：L3 独立转载判定（最容易出错的一步）

同一篇报道可能被几十家站点转载，**这不等于几十个信源**。

判定独立性的检查项：

| 检查 | 结论 |
|---|---|
| 页面写 `Source: SCMP` / `via` / `据《南华早报》` | 同一稿源，**不独立** |
| 内容与原文 L1/L2 逐字一致 | 同一稿源，不独立 |
| 通讯社（路透/AP/塔斯社/法新社）**自行采访发布** | 独立信源 ✅ |
| 官方通稿 / 官方数据库 | 独立信源 ✅（最高） |
| 无署名聚合站、AI 摘要站 | 只能作线索，**不得作证据** |

### 转载漂移清单（逐项核对，命中即降级）

- **日期漂移**：本案聚合站把 9 月 9 日（原文 `7:00pm, 9 Sep`）写成 9 月 8 日。
- **作者漂移**：转载站不带署名，二次传播后变成「无主报道」，再被引成「据报道」。
- **数字漂移**：区间被压成单值、币种/单位被改（千立方米→立方米）。
- **措辞升级**：原意为「将在双边场合讨论」，转载后变成「可能推动突破」；「处于过渡最后阶段」变成「即将开工」。**这类升级是虚假信息最常见的生成机制。**
- **细节无源**：转载摘要里出现原文 L1/L2 不可能有的具体细节（人名、数字、日期）→ 该细节按编造处理，除非另有独立来源。

## 第五步：L4 外部交叉验证

墙后的关键细节（人名、机构、表态、公报内容）必须找**另一条独立链路**验证：

- 政府/机构官网通稿全文（本案：中国政府网《习近平会见俄罗斯总统普京》通稿，直接验证「未提及该项目」）。
- 通讯社快讯（路透、塔斯社、俄卫星社）。
- 当事人所在机构的公开发布、记者会实录。
- 对方口径的官方媒体（用作反证或限定范围）。

## 判定规则

| 情况 | 处理 |
|---|---|
| L1+L2 已足够支撑子命题 | 判定「真实」，注明取证层级 |
| 细节来自 L3，且 L4 有独立佐证 | 可判定，但报告须说明「该细节取自对该报道的多个独立转述」 |
| 细节仅来自 L3，无 L4 佐证 | 该子命题写 **「无法证实」** |
| L3 之间互相矛盾 | 写「说法不一」，列出各版本与出处，不取平均、不拼盘 |
| 原文本身只是「援引匿名知情人士」 | 在结论中标注信源性质——**匿名信源不能当作一手证实**，即使它来自大报 |

## 报告写法（可直接套用）

**证据来源表述**

> 《南华早报》原文处于付费墙后。本核查据其公开可见的元数据与正文段落（标题、作者、发布时间、导语、价格段、远东路线段）直接取证；涉及改名／乌沙科夫／公报的三处细节取自对该同一篇报道的多个转载摘要，并已由路透社、塔斯社、俄卫星社及中国政府网通稿交叉验证。

**存档提示**

> 核查涉及的原始链接建议先行存档（`archive.org` / `archive.today` / `perma.cc`）后再对外引用，以防原页变更。

**禁止**

- ❌ 写「据报道」而不给出是哪家、哪篇、哪一天。
- ❌ 把 L3 转述写成本次核查直接读到原文。
- ❌ 用聚合站的日期覆盖原文时间戳。
